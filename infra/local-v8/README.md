# NEXUS v8 — LOCAL Docker staging (Windows 10)

This directory is a **separate disposable sandbox**. Do not run the repository root `docker-compose.yml` for this task: it uses a different project, ports and volumes. These instructions never deploy to Render or reach production by design.

## Architecture

| Resource | Sandbox configuration |
| --- | --- |
| PostgreSQL + PostGIS | `postgis/postgis:16-3.4` directly (PostgreSQL 16 with PostGIS) |
| Redis | `redis:7-alpine`, password-protected, no persistent volume |
| Compose project | `nexus-v8-local` (dedicated named PostgreSQL volume) |
| DB host binding | `127.0.0.1:55488` -> container 5432 |
| Redis host binding | `127.0.0.1:56388` -> container 6379 |
| Backend candidate | `127.0.0.1:33188`, **not started here** |
| Container network | Dedicated Compose bridge; not attached to any existing Docker networks. Host ports bound only to 127.0.0.1. Containers may have outbound access, so never reuse production credentials. |

Passwords and local JWT keys are generated by `bootstrap.ps1` and saved in ignored `.env.local` / `.env.backend.local`. Neither is committed. The repository's top-level `.env` is deliberately **not** used.

## Step 0 — prerequisites

- Docker Desktop running with Linux containers / WSL 2 backend.
- PowerShell 5.1+ and Docker Compose v2 (`docker compose version`).
- Free localhost ports **55488** and **56388**. These avoid the existing development defaults 5432/6379 and Supabase local DB port 54322.
- Repository cloned locally, Node.js 22+ available only for optional migrations.

In PowerShell **at the repository root**, run:

```powershell
docker desktop status
docker compose version
Test-NetConnection 127.0.0.1 -Port 55488
Test-NetConnection 127.0.0.1 -Port 56388
```

Both ports should be unused before starting Docker. A failed connection indicates *available* ports; check existing Docker containers too. Do not stop other services automatically.

## Step 1 — generate local-only secrets

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\infra\local-v8\bootstrap.ps1
```

This refuses to overwrite an existing configuration; keep existing data/secrets unless you intentionally start fresh. Do not paste generated `.env*` files into chats, issues or CI.

## Step 2 — start only the dedicated Compose stack

```powershell
docker compose --env-file infra/local-v8/.env.local -f infra/local-v8/compose.yaml config --quiet
docker compose --env-file infra/local-v8/.env.local -f infra/local-v8/compose.yaml up -d --wait
docker compose --env-file infra/local-v8/.env.local -f infra/local-v8/compose.yaml ps
```

Only `postgres` and `redis` services should appear under Compose project `nexus-v8-local`. This does **not** start NestJS or run migrations.

The first run downloads the PostGIS image if not cached. The existing root Dockerfile currently relies on a discontinued PGDG apt repository; this sandbox does not use it. NEXUS computes H3 cells in application code; no PostgreSQL `h3` extension is needed for this smoke test.

## Step 3 — verify isolation and health

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\infra\local-v8\smoke.ps1
```

Expected: **PASS** for DB identity `nexus_v8/nexus_v8`, PostGIS availability, Redis `PONG` and loopback-only bindings. The smoke test is read-only and does not install extensions, seed users or run migrations.

For independent container inspection:
```powershell
docker compose --env-file infra/local-v8/.env.local -f infra/local-v8/compose.yaml ps
docker compose --env-file infra/local-v8/.env.local -f infra/local-v8/compose.yaml logs --tail 20 postgres redis
```
Avoid printing full `docker compose config` or `docker inspect` results: these can contain credentials.

## Step 4 — optional reviewed local migrations (not automatic)

The repository migration runner creates real tables and requires a *fresh* isolated DB. First run the dry check:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\infra\local-v8\migrate-local.ps1
```

Only after migration history and SQL have been reviewed against the new empty sandbox, explicitly opt in:
```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\infra\local-v8\migrate-local.ps1 -Apply
```

The wrapper checks loopback host, port, database, user and the Compose Postgres binding before setting a process-scoped `DATABASE_URL`. It deliberately never accepts a production URL. Migrations are **not** a prerequisite for the initial PostGIS/Redis smoke test and have not been run as part of this PR.

**Backend startup is intentionally not automated yet.** `apps/backend/src/main.ts` loads the repository `.env`, so a dedicated v8 runtime guard and clean environment launch are needed before enabling real test-account login or Socket.IO. `.env.backend.local` is a staging candidate only, not a ready-to-deploy backend credential source. No production ID, SMS, Stripe, S3 or OAuth providers should be connected to this sandbox.

## Stop, restart and explicit destruction

```powershell
docker compose --env-file infra/local-v8/.env.local -f infra/local-v8/compose.yaml stop
docker compose --env-file infra/local-v8/.env.local -f infra/local-v8/compose.yaml start
```

To remove *only* this staging stack's containers and network while preserving its PostgreSQL volume:

```powershell
docker compose --env-file infra/local-v8/.env.local -f infra/local-v8/compose.yaml down
```

**Destructive, only after intentionally discarding all test data:** add `--volumes` to that exact command. Never run `docker volume prune`, generic `docker compose down -v` from the root directory, or commands against existing `g88-postgres` / Supabase containers.

## Success criteria

- Only loopback publishes two nondefault ports; no 0.0.0.0 binding.
- PostGIS available on a new, dedicated DB; H3 cells are computed in application code; no production records.
- Redis authenticated, disposable and connected only to the local network.
- Stack reproducible on Windows 10 / Docker Desktop, no production secrets copied.
- Smoke script passes and no migrations or external service deployments were triggered.
- Future real backend testing is explicitly blocked until v8 runtime isolation, synthetic accounts and provider-safe toggles are verified.
